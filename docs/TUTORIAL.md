## 1. Введение и концепция проекта

Сайт **AX1S_TEAM** создан как цифровой манифест креативно-технологической студии. В основу визуального повествования заложена философия сюрреализма:
- **Сальвадор Дали**: текучесть времени, тающие формы, пластичность материи, органические метаморфозы.
- **Рене Магритт**: визуальная ирония («Это не яблоко»), скрытые смыслы, кристаллическая геометрия за завесой очевидного.

Главный визуальный акцент сайта — **жидкий 3D-блоб**, который живёт не внутри ограниченного первого экрана, а **бесшовно сопровождает пользователя по всей длине лендинга**, меняя траекторию, форму, физическое состояние и цветовую палитру в тон каждой смысловой секции.

В качестве эталона физики и пластики выбран всемирно известный проект **Blobmixer от студии 14islands**. Главные качества этой анимации:
1. **Никакой угловатости**: форма всегда гладкая, бархатистая, без острых заломов и самопересечений сетки.
2. **Ощущение осязаемой вязкости**: при скролле или драге объект ведёт себя как капля плотного силикона или мёда — упруго вытягивается по вектору движения, округляется от поверхностного натяжения и вибрирует мягкой рябью.
3. **Двухкомпонентный лаковый блик (Dual-Lobe Clearcoat)**: рассеянный сатиновый свет тела капли в сочетании с зеркальным точечным бликом верхнего прозрачного слоя лака.

## 3. Сквозная 3D-сцена: как рендерить Three.js на всю длину страницы

### Проблема классического подхода
Частая ошибка начинающих разработчиков — создавать отдельный `<Canvas>` в секции Hero и ещё один `<Canvas>` в секции кейсов или навыков. Это приводит к:
1. Созданию двух и более контекстов WebGL, что пожирает видеопамять (VRAM) на мобильных устройствах.
2. Разрыву анимации при скролле: 3D-объект первого экрана исчезает за пределами экрана.
3. Просадкам FPS при инициализации новых сцен.

### Архитектурное решение в AX1S_TEAM: Единый фиксированный слой
В проекте реализован ровно **один** глобальный Canvas, закреплённый на весь экран:
```tsx
// src/components/three/WorldCanvas.tsx
<div className="pointer-events-none fixed inset-0 z-0" aria-hidden="true">
  <World />
</div>
```
- Слой `WorldCanvas` имеет CSS-свойства `fixed inset-0 pointer-events-none`. Он не блокирует клики по ссылкам и тексту вёрстки.
- Интерактивная зона перетаскивания блоба создаётся отдельным прозрачным элементом (`RelicHitbox.tsx`), который позиционируется точно над блобом на первом экране и перехватывает жесты `pointerdown`, `pointermove`, `pointerup`.

### Синхронизация состояния через `world-store.ts`
Чтобы React-компоненты страниц и 3D-цикл Three.js `useFrame` обменивались данными со скоростью 60-120 FPS без лишних ре-рендеров React-дерева, используется реактивный стор на базе паттерна издатель-подписчик (Pub/Sub):

```ts
// src/lib/world-store.ts
export type WorldSnapshot = {
  scroll: number;          // Прогресс скролла от 0.0 до 1.0
  scrollVelocity: number;  // Мгновенная скорость скролла (px/frame)
  mouseX: number;          // Нормализованные координаты курсора (-1 .. 1)
  mouseY: number;
  dragX: number;           // Смещение блоба при перетаскивании
  dragY: number;
  dragVx: number;          // Скорость сброса после перетаскивания
  dragVy: number;
  wobble: number;          // Тактильная отдача после клика
  dragging: boolean;       // Флаг активного зажатия мышью
  essence: Essence;        // Текущая морфологическая форма (0..3)
  pulseExpansion: number;  // Дыхательный цикл (GSAP)
  pulseGlow: number;
  inView: boolean;         // Активность вкладки браузера
};
```
Связка со скроллом в `WorldCanvas.tsx`:
```ts
const trigger = ScrollTrigger.create({
  trigger: document.documentElement,
  start: "top top",
  end: "bottom bottom",
  scrub: 0.5,
  onUpdate: (self) => {
    world.patch({
      scroll: self.progress,
      scrollVelocity: self.getVelocity() || 0,
    });
  },
});
```

## 4. Математика и физика движения (Blobmixer Liquid Physics)

Настоящее ощущение «жидкой ртути» или «силиконовой капли» складывается из 5 физических компонентов, работающих синхронно каждый кадр (`useFrame` в `World.tsx`).

### Squash & Stretch (упругое сжатие и растяжение)
В классической анимации Disney и физике несжимаемых жидкостей объём тела обязан оставаться постоянным:
$$V = X \cdot Y \cdot Z \approx \text{const}$$

Когда пользователь быстро крутит страницу вниз или вверх, возникает сила вязкого трения:
1. Вычисляется коэффициент растяжения по вертикали на основе скорости скролла $v$:
   ```ts
   const stretchY = 1.0 + Math.min(0.18, Math.abs(v) * 0.015);
   ```
2. Чтобы объём не раздувался, горизонтальные оси $X$ и $Z$ синхронно сжимаются:
   ```ts
   const compressXZ = 1.0 / Math.sqrt(stretchY);
   phys.scrollSquash.lerp(new Vector3(compressXZ, stretchY, compressXZ), 0.18);
   ```
В результате при энергичном скролле блоб изящно вытягивается вдоль траектории движения, не превращаясь в бесформенную массу.

### Поверхностное натяжение и округление при движении (Motion Roundness)
В покое капля может иметь сложную сюрреалистическую форму (выступы, лепестки, грани кристалла). Но в гидродинамике любое быстрое движение жидкости сквозь среду заставляет силы поверхностного натяжения сглаживать все асимметрии и стремиться к **минимальной площади поверхности — сфере**.

В коде вычисляется суммарная скорость движения капли от скролла и перетаскивания курсором:
```ts
const dragSpeed = Math.hypot(phys.vel.x, phys.vel.y);
const motionSpeed = Math.min(1.0, Math.abs(v) * 0.08 + dragSpeed * 0.45 + (w.dragging ? 0.4 : 0.0));
phys.motionRoundness += (motionSpeed - phys.motionRoundness) * 0.14;
```
В вершинном шейдере коэффициент `uMotionRoundness` плавно подавляет морфологические неровности и производит сферическую релаксацию:
```glsl
// Подавление асимметрии при движении
float shapeRetention = 1.0 - roundFactor * 0.85;

// Сферическая релаксация сетки к гладкой капле
p = mix(p, normalize(p) * length(basePos), roundFactor * 0.45);
```

### Поверхностная рябь жидкости (Surface Ripples)
Когда жидкость ускоряется, по её внешней границе пробегают микроволны капиллярной ряби.
В `World.tsx` амплитуда ряби возрастает при движении:
```ts
const targetRippleAmp = Math.min(1.0, Math.abs(v) * 0.06 + dragSpeed * 0.4 + (w.dragging ? 0.5 : 0.0));
phys.rippleAmp += (targetRippleAmp - phys.rippleAmp) * 0.16;
phys.ripplePhase += (3.8 + Math.abs(v) * 0.15 + dragSpeed * 0.9) * dt;
```
В вершинном шейдере интерференция трёх гармоник создаёт живую рябь на нормалях:
```glsl
if (uRippleAmp > 0.002) {
  float wave1 = sin(basePos.y * 14.0 - uRipplePhase * 3.4 + basePos.x * 5.0);
  float wave2 = sin(length(basePos.xz) * 18.0 - uRipplePhase * 3.0);
  float wave3 = cos(atan(basePos.z, basePos.x + 0.0001) * 3.0 + basePos.y * 7.0 - uRipplePhase * 2.2);
  float ripple = (wave1 * 0.5 + wave2 * 0.35 + wave3 * 0.15) * uRippleAmp * 0.085;
  p += baseNorm * ripple;
}
```

### Непрерывное осевое вращение при скролле (Axial Spin)
Блоб непрерывно вращается вокруг своей вертикальной оси $Y$:
```ts
const baseScrollSpin = w.scroll * Math.PI * 6.0; // 3 полных оборота на всю длину сайта
phys.axialRotation += (v * 0.045 + 0.10) * dt;
g.rotation.y = baseScrollSpin + phys.axialRotation + phys.drag.x * 0.4;
```
Благодаря этому пользователь видит объект со всех ракурсов в процессе чтения страницы.

### Пружинная физика интерактивного перетаскивания (Spring Physics)
Когда пользователь зажимает блоб мышью или пальцем и тянет в сторону:
1. Записывается вектор смещения и скорость перемещения курсора.
2. При отпускании объект не телепортируется назад мгновенно, а рассчитывается классическая возвратная пружина Гука с коэффициентом вязкого демпфирования:
   $$F = -k \cdot x - c \cdot v$$
   где $k = 38.0$ (жёсткость пружины), $c = 6.2$ (вязкое сопротивление среды).
```ts
const springK = 38.0;
const damping = 6.2;
const fx = -springK * phys.drag.x - damping * phys.vel.x;
const fy = -springK * phys.drag.y - damping * phys.vel.y;

phys.vel.x += fx * dt;
phys.vel.y += fy * dt;
phys.drag.x += phys.vel.x * dt;
phys.drag.y += phys.vel.y * dt;
```

## 5. GLSL-шейдеры блоба: глубокий разбор алгоритмов

Код шейдеров расположен в `src/components/three/blob-shader.ts`. Это сердцевины рендеринга.

### Вершинный шейдер (Vertex Shader) и 3D Simplex-шум
Вместо классического тяжелого шума Перлина на базе 3D-текстур используется аналитический **Simplex 3D Noise (Stefan Gustavson & Ian McEwan)**. Он вычисляется процедурно на GPU за доли миллисекунды.

Двухслойный октавный шум создаёт бархатистые, объёмные холмы:
```glsl
vec3 noiseCoord = p * uFrequency + vec3(sin(uWavePhase * 0.5) * 0.35, uWavePhase * 0.45, cos(uWavePhase * 0.4) * 0.35);
float n1 = snoise(noiseCoord);
float n2 = snoise(noiseCoord * 1.85 - vec3(uWavePhase * 0.25, uWavePhase * 0.2, uWavePhase * 0.3));
float rawNoise = n1 * 0.7 + n2 * 0.3;
```

### Аналитический расчёт нормалей в касательном пространстве (Tangent-Space Normals)
**Почему нельзя использовать стандартные нормали Three.js после деформации вершин?**
Когда вершины сетки смещаются шумом вдоль нормали, первоначальные нормали исходной сферы становятся некорректными. Если освещать деформированный меш старыми нормалями, свет будет выглядеть плоским, а на краях появятся грубые треугольные заломы.

Для получения гладкого зеркального блика в `blob-shader.ts` реализован метод **конечных разностей в касательном пространстве**:
1. Строятся два ортогональных касательных вектора $\vec{T}$ (касательная) и $\vec{B}$ (бикасательная):
   ```glsl
   vec3 vTangent = normalize(cross(baseNorm, abs(baseNorm.y) > 0.92 ? vec3(1.0, 0.0, 0.0) : vec3(0.0, 1.0, 0.0)));
   vec3 vBitangent = normalize(cross(baseNorm, vTangent));
   ```
2. Вычисляется деформированное положение двух соседних точек со сверхмалым шагом $\epsilon = 0.015$:
   ```glsl
   float eps = 0.015;
   vec3 posT = calculateDisplacedPosition(basePos + vTangent * eps, normalize(baseNorm + vTangent * eps));
   vec3 posB = calculateDisplacedPosition(basePos + vBitangent * eps, normalize(baseNorm + vBitangent * eps));
   ```
3. Истинная нормаль деформированной поверхности получается через векторное произведение разностей:
   ```glsl
   vec3 nDiff = cross(posT - displaced, posB - displaced);
   vec3 deformedNorm = normalize(nDiff);
   ```
Этот приём гарантирует идеально гладкие блики, как на полированном жидком стекле.

### 4 сюрреалистические формы Дали и Магритта
Морфинг между формами интерполируется параметром `uEssence` от 0.0 до 4.0:
1. **Форма 0 («Текучесть Дали»)**: тающая капля, стекающая вниз под действием гравитации:
   ```glsl
   float droop = smoothstep(-0.35, 1.25, -p.y) * 0.26 * shapeRetention;
   morph0.y -= droop * (1.0 + sin(uWavePhase * 0.8 + p.x * 1.5) * 0.12);
   morph0.xz *= (1.0 + droop * 0.16);
   ```
2. **Форма 1 («Подмена Магритта»)**: сюрреалистическое яблоко с верхней впадинкой у плодоножки и мягким экваториальным поясом:
   ```glsl
   float appleDimple = smoothstep(0.4, 1.25, p.y) * 0.22 * shapeRetention;
   morph1.y -= appleDimple;
   float ring = sin(length(p.xz) * 5.2 - uWavePhase * 0.9) * 0.11 * smoothstep(1.2, 0.2, abs(p.y)) * shapeRetention;
   morph1 += baseNorm * ring;
   ```
3. **Форма 2 («Сокрытие Магритта»)**: округлый кристалл-желе, огранённый мягкими полигональными плоскостями.
4. **Форма 3 («Метаморфоза Дали»)**: 5-лепестковая пульсирующая звезда с гладкими округлыми лепестками.

Интерполяция между ними непрерывна и не имеет стыков (`mix` с функцией `smoothstep`).

### Фрагментный шейдер (Fragment Shader): глянец, радужная плёнка и SSS
Фрагментный шейдер собирает воедино 7 оптических слоёв:
1. **Процедурное студийное окружение (`getStudioReflection`)**:
   Вместо загрузки тяжёлой HDRI-карты на 5–10 МБ, отражения студийных софтбоксов (верхний, левый фиолетовый, правый бирюзовый, нижний коралловый) генерируются процедурно через `smoothstep(refDir)`. Это даёт моментальную загрузку сайта.
2. **Тонкоплёночная иридесценция (Thin-Film Iridescence)**:
   Переливы радужных цветов зависят от угла обзора $\vec{N} \cdot \vec{V}$, локального шума и фазы времени. Радужные каналы R, G, B сдвигаются с хроматической аберрацией:
   ```glsl
   float refrSpread = 0.038 + vFresnel * 0.035;
   vec3 iridR = sampleBlobSpectrum(iridPhase - refrSpread);
   vec3 iridG = sampleBlobSpectrum(iridPhase);
   vec3 iridB = sampleBlobSpectrum(iridPhase + refrSpread);
   ```
3. **Подповерхностное рассеивание (Subsurface Scattering, SSS)**:
   Имитирует прохождение света сквозь мармеладную полупрозрачную субстанцию при взгляде против источника света:
   ```glsl
   float sss = pow(max(dot(view, -lightDir), 0.0), 2.8) * 0.65;
   vec3 sssGlow = mix(sectionColorB, uGold, 0.45) * sss;
   ```
4. **Двухкомпонентный лаковый блик (Dual-Lobe Clearcoat)**:
   - Сатиновый базовый блик: $\text{satinSpec} = (\vec{N} \cdot \vec{H})^{18} \cdot 0.35$
   - Острый зеркальный лак: $\text{clearcoatSpec} = (\vec{N} \cdot \vec{H})^{110} \cdot 0.95$

## 6. Пространственная хореография блоба вдоль страницы

Траектория движения блоба запрограммирована в функции `getBlobPath(t, mobile)` в файле `World.tsx`.

```
Экран Hero (t = 0.0):
┌─────────────────────────────────────────────────────────────┐
│  Форма врёт.                        [ 3D BLOB ]             │
│  Бренд остаётся.                    (x = 1.30, y = 0.16)    │
│  [Кнопка] [Кнопка]                  (scale = 0.74)          │
└─────────────────────────────────────────────────────────────┘
                                ↓ скролл
Секция Manifest (t = 0.16):
┌─────────────────────────────────────────────────────────────┐
│  [ 3D BLOB ]                        Манифест студии         │
│  (x = -1.25, y = 0.05)              «Мы создаём цифровые    │
│                                     артефакты...»           │
└─────────────────────────────────────────────────────────────┘
                                ↓ скролл
Секция Work (t = 0.38):
┌─────────────────────────────────────────────────────────────┐
│  Кейсы и проекты                    [ 3D BLOB ]             │
│                                     (x = 1.28, y = -0.05)   │
└─────────────────────────────────────────────────────────────┘
```

### Принцип «визуального баланса» (Rule of Clear Margins)
1. **Никаких случайных перекрытий**: на десктопе блоб попеременно занимает открытую правую либо открытую левую колонку сетки (12-колоночный ритм), оставляя текстовые блоки свободными для комфортного чтения.
2. **Плавная интерполяция Hermite**: переход между координатами происходит не линейно, а по сглаженной кривой Безье:
   $$f(p) = p^2 \cdot (3 - 2p)$$
3. **Мобильная адаптация**: на смартфонах с шириной экрана $< 768\text{px}$ блоб переводится в «режим парения» над заголовками ($y = 0.60$, масштаб уменьшен до $0.55$).

## 7. Реактивная типографика: подсветка текста при касании блобом

Когда пользователь уменьшает размер окна или когда блоб переплывает из колонки в колонку, он может приблизиться к тексту. Вместо того чтобы текст становился нечитаемым, внедрена **реактивная подсветка в экранном пространстве**.

### Алгоритм работы:
1. В `World.tsx` в цикле `useFrame` 3D-координата центра блоба проецируется на 2D-плоскость экрана монитора с помощью матриц камеры:
   ```ts
   screenProj.set(g.position.x, g.position.y, g.position.z).project(state.camera);
   const bx = (screenProj.x * 0.5 + 0.5) * window.innerWidth;
   const by = (-screenProj.y * 0.5 + 0.5) * window.innerHeight;
   const br = path.scale * 0.92 * (window.innerHeight * 0.30); // Экранный радиус блоба в px
   const threshold = br * 1.25;                                // Радиус влияния
   ```
2. Находятся все текстовые элементы с атрибутом `data-blob-touch`. Для каждого вычисляется кратчайшее расстояние от центра блоба до прямоугольника `getBoundingClientRect()`.
3. Если $\text{dist} < \text{threshold}$, элементу выставляется атрибут `data-touching="true"`.
4. В `src/app/globals.css` срабатывает высококонтрастный стиль:
   ```css
   [data-blob-touch] {
     transition: color 0.3s cubic-bezier(0.16, 1, 0.3, 1),
                 text-shadow 0.3s cubic-bezier(0.16, 1, 0.3, 1),
                 opacity 0.3s cubic-bezier(0.16, 1, 0.3, 1);
     will-change: color, text-shadow;
   }

   [data-blob-touch][data-touching="true"],
   [data-blob-touch][data-touching="true"] * {
     color: #ffffff !important;
     opacity: 1 !important;
     text-shadow:
       0 1px 3px rgba(8, 7, 26, 0.98),
       0 0 1px rgba(8, 7, 26, 0.95),
       0 0 16px rgba(63, 224, 197, 0.9),
       0 0 32px rgba(169, 139, 255, 0.8) !important;
   }
   ```
Текст мгновенно приобретает чистый белый цвет, тёмный контур и мягкую неоновую ауру, оставаясь кристально читаемым даже на фоне самого яркого блика блоба.

## 9. Пошаговый туториал: как собрать такой сайт с нуля

Если вы хотите повторить этот результат в новом чистом проекте, выполните следующие шаги:

### Шаг 1: Инициализация проекта Next.js
```bash
npx create-next-app@latest my-blob-studio --typescript --tailwind --eslint --app --src-dir
cd my-blob-studio
```

### Шаг 2: Установка зависимостей Three.js, GSAP и Lenis
```bash
npm install three @types/three @react-three/fiber gsap lenis
```

### Шаг 3: Настройка цветовой палитры и переменных
В `src/app/globals.css` добавьте базовые CSS-переменные:
```css
:root {
  --c-void: #08071a;
  --c-violet: #a98bff;
  --c-teal: #3fe0c5;
  --c-coral: #ff7a68;
  --c-gold: #f4c55a;
  --c-indigo: #5b4bff;
  --c-mist: #efeaf8;
  --background: var(--c-void);
  --foreground: var(--c-mist);
}
```
Создайте TS-зеркало в `src/lib/palette.ts` для чтения этих токенов WebGL-сценой через `getComputedStyle`.

### Шаг 4: Создание хранилища состояний `world-store.ts`
Создайте реактивный объект `world` с методами `get()`, `patch()`, `subscribe()`, чтобы передавать скролл и движение мыши в 3D-сцену без ре-рендеров React.

### Шаг 5: Написание GLSL-шейдеров
Скопируйте вершинный и фрагментный шейдеры из `src/components/three/blob-shader.ts`:
- Внедрите функцию 3D Simplex-шума `snoise(vec3 v)`.
- Реализуйте функцию `calculateDisplacedPosition` со Squash & Stretch, поверхностным натяжением `uMotionRoundness` и бегущей рябью.
- Обязательно добавьте блок расчёта нормалей в касательном пространстве (`vTangent`, `vBitangent`).
- Во фрагментном шейдере соедините процедурные софтбоксы, иридесценцию и двухкомпонентный блик.

### Шаг 6: Сборка Three.js компонента (`World.tsx` и `WorldCanvas.tsx`)
1. Создайте `icosahedronGeometry` с радиусом `0.92` и детализацией `detail = 4`.
2. Оберните меш в `ShaderMaterial` со своими униформами.
3. В хуке `useFrame` обновляйте униформы, считывая `world.get()`.
4. Создайте компонент `CameraRig`, управляющий положением камеры.
5. Оберните сцену в динамический импорт без SSR:
   ```tsx
   const World = dynamic(() => import("@/components/three/World"), { ssr: false });
   ```

### Шаг 7: Подключение Lenis и связка с GSAP ScrollTrigger
Создайте `src/lib/lenis.tsx`:
- Инициализируйте экземпляр `Lenis`.
- Добавьте `lenis.raf` в тикер GSAP: `gsap.ticker.add((time) => lenis.raf(time * 1000))`.
- Слушайте событие `lenis.on('scroll')` и передавайте `progress` и `velocity` в `world.patch()`.

### Шаг 8: Вёрстка секций и добавление реактивного текста
1. Разместите секции одна под другой (`Hero`, `Manifest`, `Work`, `Practices`, `Contact`).
2. Назначьте заголовкам атрибут `data-blob-touch`.
3. В `World.tsx` добавьте проецирование координат блоба на экран (`screenProj.project(camera)`) и переключение атрибута `data-touching="true"`.

### Шаг 9: Проверка сборки и оптимизация
```bash
npm run typecheck
npm run build
npm run start
```
Проверьте сайт в Chrome DevTools:
- Частота кадров должна держаться на стабильных 60 FPS (120 FPS на экранах с ProMotion).
- При переключении вкладок рендеринг должен корректно засыпать (`visibilitychange`), экономя ресурсы пользователя.
- При изменении размера окна и на мобильных устройствах блоб должен аккуратно уступать место типографике.
